# 截屏翻译工具 —— 需求分析与技术实现方案

> 目标：Windows 平台、Snipaste 式交互（全局热键 → 冻结屏幕 → 框选 → 自动 OCR + 翻译），
> 必须正确处理多显示器、混合 DPI、不同分辨率。
>
> 本文档为 v1 设计基线，技术栈以 **Python 3.11/3.12 + PySide6(Qt6) + ctypes/Win32** 为主，
> 文末给出 C#/Rust 备选方案对比。

---

## 1. 产品定位

| 项 | 内容 |
|---|---|
| 一句话 | 按一下键，框一块屏幕，原地看到译文 |
| 对标 | Snipaste 的截图/贴图交互 + 沉浸式翻译的呈现方式 |
| 平台 | Windows 10 1903+ / Windows 11，x64 |
| 核心差异 | 不是"截图工具加翻译"，而是**翻译优先**：选区完成即出结果，无需二次确认 |
| 非目标（v1） | 实时全屏翻译、视频字幕、PDF 翻译、macOS/Linux |

---

## 2. 核心用户流程

```
[全局热键 Alt+Q]
      │  ≤80ms
      ▼
[冻结层] 所有显示器画面定格 + 整体压暗 + 十字光标 + 放大镜
      │  拖拽框选（可跨屏）
      ▼
[选区确认：松开鼠标 / Enter / 双击]
      │
      ├─ 立即：把原图裁切块贴到结果卡上（感知延迟≈0）
      ├─ 后台：预处理 → OCR → 行合并 → 翻译（流式）
      ▼
[结果呈现] 二选一（可配置）
   A. 悬浮卡片：原图 + 原文/译文对照，可拖动、置顶、复制
   B. 原地覆盖：译文直接盖在原文位置，背景色自适应
      │
      ▼
[Esc / 点击外部 关闭]  或  [钉住 Pin，像 Snipaste 贴图一样留在屏幕上]
```

失败分支：没识别到文字 → 卡片提示"未检测到文本"，保留原图可复制；网络失败 → 显示原文 + 重试按钮。

## 5. 技术选型

### 5.1 语言 / UI 框架

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Python + PySide6 (Qt6)** | 开发最快；Qt 绘图/透明窗口成熟；OCR/翻译生态最好 | 包体大（~120MB）；Qt 多屏 DPI 有坑；GIL 对并发无碍（IO 密集） | **推荐（v1）** |
| C# + WPF/WinUI3 | 原生 Win32/WinRT 调用最顺；WGC 直接可用；包体小 | OCR 生态弱（要 PaddleSharp/ONNX）；开发慢 | 备选（追求极致体验时） |
| Rust + egui/tauri | 性能与包体最优 | 开发成本高；UI 细节打磨慢 | 不推荐首版 |
| Electron | 生态好 | 500MB+，内存高，不符合工具定位 | 排除 |

> 注意：当前机器是 **Python 3.13**。PySide6 6.8+ 与 onnxruntime 1.20+ 都支持 3.13，
> 但 **PaddlePaddle 对 3.13 支持滞后**。因此：
> - 走 **RapidOCR（onnxruntime）** 路线可直接用 3.13；
> - 若坚持 PaddleOCR 原生推理，建议建 3.11/3.12 的 venv。

### 5.2 截图 API

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **BitBlt（GDI）** | 抓屏幕 DC | 极简、无依赖、单帧 <15ms | 硬件加速内容可能黑屏；受 DPI 虚拟化影响；HDR 失真 |
| **DXGI Desktop Duplication**（`dxcam`） | D3D11 复制输出 | 最快（<5ms） | 混合显卡/RDP/部分独占全屏会失败；代码复杂 |
| **Windows.Graphics.Capture**（`windows-capture` 包） | WinRT 合成器捕获 | 官方推荐路径；可抓单窗口；含光标开关；质量最好 | 需 D3D11 互操作；延迟略高于 DXGI；Win10 1903+ |
| **PrintWindow** | 让窗口自绘 | 可抓被遮挡窗口 | 很多程序不响应；不适用全屏定格 |

**推荐策略：降级链**
```
WGC(windows-capture) → DXGI(dxcam) → BitBlt(mss / 自写 ctypes)
```
v1 先上 **BitBlt** 跑通全流程（覆盖 95% 桌面场景），把 `ICaptureBackend` 抽象好，
M4 再补 WGC。不要在第一天就啃 WGC 的 COM 互操作。

> 关键点：**先设置 Per-Monitor V2 DPI 感知，再截图**，否则 BitBlt 拿到的是被系统缩放后的
> 模糊位图，且坐标系与物理像素不一致。

### 5.3 OCR

| 引擎 | 中文精度 | 包体 | 速度(1000×600, CPU) | 打包难度 | 结论 |
|---|---|---|---|---|---|
| **RapidOCR (onnxruntime)** | ★★★★☆ | 模型 ~15MB + ort ~15MB | 150–350ms | 低（pip 即用） | **推荐默认** |
| PaddleOCR (paddle 推理) | ★★★★★ | 300MB+ | 200–400ms | 高（paddle 依赖重） | 可选高精度模式 |
| Windows.Media.Ocr | ★★★☆ | 0（系统自带） | 50–150ms | 极低 | **保底/首启兜底** |
| Tesseract | ★★ | 30MB+ | 300ms+ | 中 | 排除（UI 小字差） |
| 云端 OCR（百度/腾讯/阿里） | ★★★★★ | 0 | 300–800ms + 网络 | 低 | 可选，隐私敏感场景关闭 |

推荐：**默认 RapidOCR，系统 OCR 做兜底，云端做可选**。
三者实现同一个 `OcrEngine` 接口，结果统一为 `[{text, box, score}]`。

### 5.4 翻译

| 方案 | 质量 | 延迟 | 成本 | 适用 |
|---|---|---|---|---|
| **LLM（DeepSeek / OpenAI 兼容）** | ★★★★★ 语境、术语、长句都强 | 0.6–2s（可流式） | 低 | **推荐默认** |
| DeepL API | ★★★★☆ | 200–500ms | 中 | 追求速度/稳定 |
| 百度/腾讯翻译 | ★★★☆ | 200–400ms | 低 | 国内网络稳 |
| 本地 LLM（Ollama/Qwen） | ★★★☆ | 1–3s | 0 | 纯离线/隐私模式 |

**核心设计：一次请求翻整个选区，而不是逐行调用。**
把 OCR 行编成 JSON 数组 `[{id, text}]` 一次发出，要求模型返回同 id 的译文数组。
好处：① 上下文完整，术语一致；② 只一次 RTT；③ id 保证译文与 bbox 一一对应，方便回填。

## 6. 核心难点一：多显示器与 DPI（最容易翻车的地方）

### 6.1 三层坐标系必须先理清

```
① 物理像素坐标（Physical, Win32 原生）
   - GetSystemMetrics(SM_XVIRTUALSCREEN...) / GetMonitorInfo / BitBlt 都用它
   - 可能是负数（副屏在主屏左侧/上方时）
   - 整个虚拟桌面范围 = 所有显示器矩形的并集

② Qt 逻辑坐标（Logical / device-independent）
   - Qt6 默认开启高 DPI 缩放，窗口几何、鼠标事件都是逻辑像素
   - 逻辑 = 物理 / devicePixelRatio（每块屏 dpr 不同）

③ 图像像素坐标（Image）
   - 截出来的 QImage 是物理像素，1:1 对应 ①
```

**规则：内部一律用物理像素存储和计算；只在"画到 Qt 窗口"这一层做物理→逻辑转换。**

### 6.2 进程 DPI 感知（必须在 QApplication 之前）

```python
import ctypes
user32 = ctypes.WinDLL("user32", use_last_error=True)

# DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2 == -4
# 返回值 0 表示失败（老系统无此 API，回退 SetProcessDpiAwareness(2)）
if not user32.SetProcessDpiAwarenessContext(ctypes.c_void_p(-4)):
    try:
        ctypes.WinDLL("shcore").SetProcessDpiAwareness(2)  # PROCESS_PER_MONITOR_DPI_AWARE
    except Exception:
        user32.SetProcessDPIAware()                        # 最后兜底：系统级
```

必须在 `QApplication(...)` 构造之前执行。Qt6 默认也会设 Per-Monitor V2，
但**显式调用更可控**，且能保证在 Qt 之前就生效（否则首次 `GetSystemMetrics` 会拿到缩放值）。

验证方法：在 150% 缩放的屏上，`GetSystemMetrics(SM_CXSCREEN)` 应返回物理宽度（如 2560），
而不是 1707。

### 6.3 显示器枚举（以 Win32 为准，不信 Qt）

```python
class MONITORINFOEXW(ctypes.Structure):
    _fields_ = [("cbSize", wintypes.DWORD), ("rcMonitor", wintypes.RECT),
                ("rcWork", wintypes.RECT), ("dwFlags", wintypes.DWORD),
                ("szDevice", wintypes.WCHAR * 32)]

def enum_monitors():
    out = []
    MONITORENUMPROC = ctypes.WINFUNCTYPE(wintypes.BOOL, wintypes.HMONITOR,
                                         wintypes.HDC, ctypes.POINTER(wintypes.RECT),
                                         wintypes.LPARAM)
    def cb(hmon, hdc, lprc, data):
        mi = MONITORINFOEXW(); mi.cbSize = ctypes.sizeof(mi)
        user32.GetMonitorInfoW(hmon, ctypes.byref(mi))
        out.append({
            "handle": hmon,
            "physical": (mi.rcMonitor.left, mi.rcMonitor.top,
                         mi.rcMonitor.right - mi.rcMonitor.left,
                         mi.rcMonitor.bottom - mi.rcMonitor.top),
            "primary": bool(mi.dwFlags & 1),      # MONITORINFOF_PRIMARY
            "device": mi.szDevice,                 # "\\.\DISPLAY1"
        })
        return True
    user32.EnumDisplayMonitors(None, None, MONITORENUMPROC(cb), 0)
    return out
```

物理 → Qt 的映射：`QScreen.name()` 在 Windows 上返回的正是 `\\.\DISPLAY1` 这类设备名，
用它和 `szDevice` 对齐，再取 `screen.devicePixelRatio()`。

```python
def logical_to_physical(pt: QPoint, screen: QScreen, mon: dict) -> QPoint:
    g = screen.geometry()          # 该屏在 Qt 逻辑空间中的矩形
    dpr = screen.devicePixelRatio()
    mx, my = mon["physical"][:2]
    return QPoint(mx + round((pt.x() - g.x()) * dpr),
                  my + round((pt.y() - g.y()) * dpr))
```

### 6.4 跨屏覆盖窗口：**不要用一个窗口横跨所有屏**

这是 Qt 多屏最大的坑：一个窗口只能属于一个 `QScreen`，DPR 取它所在屏的值。
如果用一个窗口铺满虚拟桌面，主屏 150% + 副屏 100% 时，副屏上的内容会被整体放大/错位，
鼠标坐标也会偏。

**方案 A（推荐）：每块屏一个冻结层窗口**

- 对每块显示器创建一个无边框、置顶、`Tool` 窗口，几何 = 该屏 `screen.geometry()`（逻辑）。
- 每个窗口只画自己那块屏的截图 → 因为窗口恰好独占一块屏，DPR 天然正确。
- 绘制：`painter.drawImage(self.rect(), screen_image)`，
  `screen_image` 是物理像素，`self.rect()` 是逻辑像素，Qt 按 DPR 自动 1:1 映射，不模糊。
- 选区跨屏时：所有窗口共享同一个"选区状态机"，各自裁剪绘制自己与选区的交集
  （`painter.setClipRect(local_rect)`），这样视觉上是一个整体。

**方案 B：单窗口 + 关闭 Qt 缩放**
`QT_ENABLE_HIGHDPI_SCALING=0`，Qt 坐标 == 物理像素，一个窗口可正确铺满。
代价：所有 UI（工具栏、提示文字）都要自己乘缩放系数，字体在 4K 上会偏小，
且 Qt6 对关闭缩放的支持不如 Qt5 稳。**不推荐。**

**方案 C：纯 Win32 分层窗口**
`WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_TOPMOST` + `UpdateLayeredWindow` / Direct2D。
控制力最强、延迟最低，但要自己实现绘制、光标、输入。**v2 可以考虑。**

### 6.5 必须覆盖的边界情况清单

| 场景 | 表现 | 处理 |
|---|---|---|
| 副屏在主屏左侧 | 坐标为负（如 x=-1920） | 全程用有符号 int，禁止假设 0 起点；Qt 逻辑坐标同样可能是负 |
| 两块屏 DPR 不同 | 单窗口方案错位 | 每屏一窗；坐标换算必须带 `mon` 参数 |
| 双屏分辨率不同 | 冻结层高度不一 | 每窗独立尺寸，不假设一致 |
| 竖屏 | 宽高倒置 | 不做任何"横屏"假设 |
| 主屏切换 | `SM_XVIRTUALSCREEN` 变化 | 每次唤起时重新枚举，不缓存 |
| 运行中改缩放/插拔显示器 | Qt 屏幕列表变化 | 监听 `QGuiApplication.screenAdded/screenRemoved`；冻结层每次重建 |
| RDP / 远程桌面 | 分辨率随窗口变化 | 同上；捕获前重新枚举 |
| HDR / 10bit | BitBlt 颜色失真 | 检测 `DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO`；v1 接受偏色，v2 用 WGC 做 tonemap |
| UAC 安全桌面 / 锁屏 | 抓不到 | 无法解决，忽略（热键也不会响应） |
| 独占全屏游戏 | BitBlt 黑屏 | 降级链到 DXGI/WGC；仍失败则提示 |
| 高对比度/深色模式 | 背景色估计错 | 见 9.3 的"气泡底"兜底 |

## 7. 核心难点二：冻结层与选区交互

### 7.1 冻结时序（必须"先抓后显"）

```
1. 隐藏自身所有窗口（结果卡、托盘弹窗）
2. 枚举显示器 → 逐屏 BitBlt 到 QImage（物理像素）
3. 创建 N 个冻结层窗口，setGeometry(screen.geometry())
4. show() + raise_() + activateWindow() + 抢焦点
5. 光标设为 CrossCursor
```

顺序反了会在截图里拍到自己。第 4 步抢焦点可能被前台程序阻止，需要：

```python
hwnd = int(self.winId())
# 前台锁定时用 AttachThreadInput 强行抢
fg = user32.GetForegroundWindow()
tid_fg = user32.GetWindowThreadProcessId(fg, None)
tid_me = kernel32.GetCurrentThreadId()
user32.AttachThreadInput(tid_me, tid_fg, True)
user32.SetForegroundWindow(hwnd)
user32.SetFocus(hwnd)
user32.AttachThreadInput(tid_me, tid_fg, False)
```

### 7.2 视觉规范（对齐 Snipaste 手感）

- 全屏压暗：`rgba(0,0,0,0.45)` 铺满，选区内部**不压暗**（用 clip 反向绘制）。
- 选区边框：1px 亮色（#00A8FF）+ 外侧 1px 半透明白，保证深浅背景都可见。
- 尺寸标签：选区左上角显示 `W × H`（物理像素），字号随 DPR 缩放。
- 8 个手柄：8×8 逻辑像素方块，边缘中点 + 四角。
- 辅助线：拖动时显示与屏幕中线/其他窗口边缘的对齐线（P1）。
- 放大镜：光标 24px 内显示 120×90 的 8 倍放大图 + 十字准星 + `#RRGGBB` + `(x, y)`。

### 7.3 选区状态机

```
IDLE ──按下──> DRAGGING ──松开──> SELECTED
                  │                  │
                  │            ┌─────┼──────────┐
                  │            ▼     ▼          ▼
                  │         移动   缩放手柄   双击/Enter
                  │            └─────┴──────────┘
                  └──Esc──> CANCEL
```

关键实现点：

- **拖拽新建**：记录 `anchor`（物理）与 `current`，矩形归一化（处理反向拖拽）。
- **手柄命中测试**：以物理像素判断，命中阈值 6/dpr 逻辑像素，避免高 DPI 下点不中。
- **最小尺寸**：< 4×4 物理像素视为误触，取消。
- **跨屏拖拽**：鼠标事件发生在某个窗口内，用 `QCursor.pos()` 取全局逻辑坐标再换算，
  不要用 `event.position()`（那是窗口内坐标）。
- **键盘**：`Enter` 确认、`Esc` 取消、方向键 ±1px、`Shift+方向键` ±10px、
  `Ctrl+A` 全屏、`Tab` 切换显示器全选、`右键` 取消。
- **双击**：`WindowFromPoint` + `GetWindowRect`（或 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`，
  后者能去掉 Win10 的隐形边框）直接选中该窗口。

> 所有窗口共享一个 `SelectionModel`（单例/信号总线），任一窗口的鼠标事件都更新它，
> 各窗口监听 `changed` 信号重绘自己的裁剪区域。这样跨屏选择和普通选择是同一套代码。

### 7.4 屏幕内容不变性

冻结层显示的是**截图**，不是实时画面。用户框选时背后的程序可能在动（视频、动画），
冻结层不会有变化——这正是 Snipaste 的体验，也让 OCR 结果与用户所见一致。
注意：**不要**在框选时重新截图，否则文案/位置可能已经变了。

## 8. 核心难点三：OCR 流水线

### 8.1 预处理（决定小字识别率）

```python
def preprocess(img: QImage) -> QImage:
    # 1) 小字放大：文本行高度 < 24 物理像素时，用 Lanczos 放大 2 倍
    #    Paddle 系模型对 ~32px 字高最敏感
    # 2) 只在"极低对比度"时才做对比度拉伸；不要二值化（会破坏抗锯齿边缘）
    # 3) 保留 RGB，不转灰度（彩色文字/高亮背景会掉字）
```
经验值：150% 缩放屏上 12pt 的界面文字，物理高度约 24px，刚好在临界点，**放大 2 倍通常能多识别 10–20%**。

### 8.2 行合并成段落（影响翻译质量）

OCR 输出是"行"，翻译需要"段"。算法：

1. 按 `y` 中心排序，`y` 区间重叠 > 50% 归为同一行（处理同一行内多个框）。
2. 行内按 `x` 排序，拼接（间距 > 1.5×字高时补空格）。
3. 相邻两行满足以下条件则并入同段：
   - 水平区间重叠 > 60%；
   - 行间距 < 1.6 × 行高；
   - 字号相近（高度比 0.75–1.33）。
4. 多栏检测：若存在两组 x 区间各自垂直连续，则先左栏后右栏。

### 8.3 语言判定

按字符集统计：CJK 字符占比 > 15% 视为中文，否则英文。混排时按"主语言"决定翻译方向，
并保留不译片段（URL、代码、快捷键、版本号）——用正则白名单：

```python
KEEP = re.compile(r"(https?://\S+|[\w.+-]+@[\w-]+\.\w+|[A-Za-z_]\w*\(\)|"
                  r"Ctrl\+\w+|Alt\+\w+|Shift\+\w+|F\d{1,2}|\bv?\d+\.\d+(\.\d+)?\b)")
```

## 9. 核心难点四：翻译与回填

### 9.1 请求构造（一次请求翻整块）

```json
// 输入
{"source_lang": "auto", "target_lang": "zh-CN",
 "lines": [{"id": 0, "text": "Save changes before closing?"}, ...]}
// 期望输出
{"lines": [{"id": 0, "text": "关闭前要保存更改吗？"}, ...]}
```

系统提示词要点：
- 角色：专业 UI 本地化译者；
- 保留占位符、变量名、快捷键、单位、标点风格；
- 术语一致：同一术语整块内译法统一；
- **必须返回与输入等长的数组，id 一一对应，不得合并/拆分行**；
- 不确定的专有名词保留原文。

失败兜底：JSON 解析失败 → 尝试从代码块提取 → 仍失败则退回逐行翻译（质量降级但可用）。

### 9.2 流式与取消

- 翻译走 SSE 流式，但**结构化 JSON 流式解析**麻烦。折中：
  - 方式一：非流式，整块返回（简单，1 次 RTT，1.5s 内可接受）；
  - 方式二：让模型按行输出 `{"id":0,"text":"..."}` 每行一个 JSONL，边到边渲染。
  - 推荐 v1 用方式一，P1 再加方式二。
- 用户重新框选时，必须能取消上一次请求：`threading.Event` + 递增 `job_id`，
  回调里校验 `job_id` 是否仍是当前值，过期直接丢。

### 9.3 两种呈现

**A. 悬浮卡片（v1 默认，稳妥）**

```
┌───────────────────────────────┐
│ [原图缩略]                     │  ← 可拖动、可 Pin
│ ─────────────────────────────  │
│ Save changes before closing?  │  ← 原文（可折叠）
│ 关闭前要保存更改吗？            │  ← 译文（主视觉，字号可调）
│ ─────────────────────────────  │
│ [复制] [重译] [原地覆盖] [×]    │
└───────────────────────────────┘
```
定位：选区的右下角外侧；放不下则翻到左侧/上方；始终限制在当前屏工作区内。

**B. 原地覆盖（P1，体验上限最高）**

三步：
1. **擦除原文**：取 bbox 外扩 2px 的边框像素中位数作为背景色。若边框颜色方差小（纯色背景），
   直接填色矩形；否则画圆角半透明"气泡底"（`rgba(255,255,255,0.92)` 或深色主题对应色），
   保证任何背景都可读。
2. **排版**：`QFontMetrics` 二分字号，从原字号开始向下试，直到宽度 ≤ bbox 宽度 × 1.05；
   仍放不下则允许行数 +1，并在垂直方向压缩行距。
3. **绘制**：译文偏长时向外扩展 bbox（覆盖到相邻空白），不要缩小到 6px 以下。

> 为什么不做"重新排版整页"：截图是位图，没有版面结构，重排必然错位。
> 原地覆盖的本质是"盖住 + 重画"，不是"重排版"。

### 9.4 缓存

```sql
CREATE TABLE cache (
  key TEXT PRIMARY KEY,      -- sha256(normalized_text + src + tgt + provider + glossary_ver)
  val TEXT NOT NULL,
  ts  INTEGER NOT NULL
);
```
内存 LRU 500 条 + SQLite 落盘 5 万条，命中率在重复调试/固定界面场景可达 40%+。

## 10. 核心难点五：结果窗口与"贴图"

- `Qt.Tool | FramelessWindowHint | WindowStaysOnTopHint`，`WA_TranslucentBackground`。
- 屏幕截图排除：`SetWindowDisplayAffinity(hwnd, 0x11 /* WDA_EXCLUDEFROMCAPTURE */)`（Win10 2004+），
  这样结果卡不会被下一次截图拍到。
- Pin 模式：`SetWindowLong(hwnd, GWL_EXSTYLE, ex | WS_EX_TRANSPARENT)` 实现鼠标穿透，
  配合 `WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha)` 调透明度。
- 多屏：结果卡记录"属于哪块屏"，拖动跨屏时重建（DPR 变了，字体/圆角要重算），
  否则会模糊。

## 11. 全局热键

```python
WM_HOTKEY = 0x0312
user32.RegisterHotKey(None, 1, MOD_CONTROL | MOD_ALT, ord('Q'))
# 失败 GetLastError()==1409 表示被占用
```
- 用**消息专用窗口**（`HWND_MESSAGE`）接收，或直接在主窗口上注册 + `QAbstractNativeEventFilter`。
- `RegisterHotKey` 的限制：不能用 `Win+*`（系统保留）；`PrintScreen` 可用但要配合 `MOD_NOREPEAT`。
- 需要"按住某键 + 鼠标侧键"这类组合时，才用 `WH_KEYBOARD_LL` 低级钩子（有被杀软误报风险）。
- 设置界面改键后先 `UnregisterHotKey` 再注册，失败要回滚到旧键并提示。

## 12. 架构与线程模型

```
┌───────────────────────────── UI 线程 (Qt) ─────────────────────────────┐
│ HotkeyFilter → AppController (状态机: idle/capturing/selecting/showing) │
│   ├─ OverlayManager   (N 个冻结层窗口 + SelectionModel)                  │
│   ├─ ResultCard       (结果卡/贴图)                                      │
│   ├─ TrayIcon / SettingsDialog / HistoryWindow                          │
│   └─ ScreenRegistry   (显示器枚举 + DPR 缓存 + 变更监听)                  │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ QThreadPool (QThread) + signal
┌───────────────▼─────────────────────────────────────────────────────────┐
│ PipelineWorker                                                          │
│   crop → preprocess → OCR → group → translate → emit(partial results)   │
│   · 每个任务带 job_id，可取消                                            │
│   · OCR 引擎常驻内存（首次加载 1–3s，启动后后台预热）                     │
└─────────────────────────────────────────────────────────────────────────┘
```

规则：
- UI 线程只做"贴图"和"画字"，**绝不做 OCR/网络**。
- 截图本身很快（<20ms），可以在 UI 线程做，避免一次跨线程拷贝；
  但 4K 多屏（>50MB QImage）建议放 worker 并直接传 `QImage`（Qt 隐式共享，零拷贝）。
- 引擎预热：启动后 2s 在后台跑一张 32×32 的假图，把模型加载进内存。
- 单实例：`CreateMutexW("Global\\ScreenshotTranslate")`，已存在则 `PostMessage` 唤醒旧实例并退出。
